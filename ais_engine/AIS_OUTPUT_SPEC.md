# AIS (Alpha Intelligence System) 核心输出规范文档
*本文档记录了 AIS 系统资讯抓取、清洗与企微触达全链路的最终统一输出标准。*

## 一、 整体排版规则 (Global Formatting)
1. **纯净单段落 (No Line Breaks)**：单条资讯内部的所有模块，**严禁使用任何换行符**，必须呈一行连续的纯文本。模块与模块之间仅保留空格间隔。
   *正确示范*：`【破局信号】:xxx 【Alpha评分】:xxx 【核心洞察】:xxx 【深度推演】:xxx 【信源链接】:xxx`
2. **多条信息间隔 (No Empty Lines)**：多条资讯拼接时，条与条之间**不保留空行**，只使用唯一的分割线断开。
   *分割线标准*：`\n━━━━━━━━━━━━━━\n` (14个特殊符号，约为早期设计的 70% 长度)。
3. **视觉降噪**：**禁止**使用任何 Markdown 星号 (`**bold**`) 及其他无意义的排版符号，确保企微纯文本环境下的最佳手机阅读体验。

## 二、 模块定义与文案规范
每条信息必须且只能包含以下5个带有 `【】` 的固定模块名称（不可遗漏）：

1. **【破局信号】**
   - **定位**：高信息密度的一句话标题。直击核心，弃用老套的“核心标题”等称呼。
2. **【Alpha评分】**
   - **定位**：0-10 的价值评分。
   - **规则**：分数必须和标题**处于同一行**，绝不单起一行。
3. **【核心洞察】**
   - **定位**：使用通俗易懂的形象比喻（举重若轻），把复杂的商业或技术颠覆性说明白。理解难度介于破局信号和深度推演之间。
4. **【深度推演】**
   - **定位**：预测和分析该技术在未来几个月可能带来的改变。
   - **禁忌**：严禁出现“焦虑”等向读者解释系统业务定位的 Meta-words。
5. **【信源链接】**
   - **定位**：附加信息的原始获取渠道 URL（作为付费版功能，目前测试阶段全局开放给所有用户）。
   - **规则**：纯文本展示 URL，不做 HTML 或 Markdown 超链接渲染。

## 三、 字数与比例限制 (Length & Ratio Constraints)
1. **模块比例 (1:2:4)**：`【破局信号】 : 【核心洞察】 : 【深度推演】` 三个模块的长度比例大致维持在 **1 : 2 : 4**。不需要绝对精准，但体感上要呈现由精炼到展开的节奏。
2. **总字数扩容 (1.5x)**：在保持极简、日常口语化、高度浓缩的基础上，将单条信息的总字数上调至前一版的 1.5 倍（总计约 **120 - 150 字符** 左右）。既能保证把话说透，又能保障合并发送时的效率。

## 四、 平台合并机制 (Batching Mechanism)
- **企微字节上限策略**：因企业微信纯文本消息具有 `2048 Bytes` 的硬性限制，系统会自动侦测拼接流的 UTF-8 长度。
- 只要累计拼接内容低于 `1800 Bytes` 安全线，就会一直合并在同一条微信消息气泡中；一旦超出，自动切割并发送，剩余内容进入下一条气泡。
